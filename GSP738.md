# GSP738 - Migrate VPC firewall rules to a global network firewall policy

Paste the blocks in order, in one Cloud Shell tab, and stay in the home folder (the lab writes exclude.txt and tag_map.json there). Every block ends with a check line, compare it with the note under the block.

## Known lab traps/bugs (read first)

1. The lab's Task 3 commands depend on a PROJECT_ID variable from its "Set your environment variables" step. If you skipped that step or Cloud Shell reconnected, the variable is empty and the tag commands fail. The blocks here read the project from a file instead, so they always work.
2. The lab exports tag_map.json but never fills it in, and its last Task 3 command does not pass it. The mapping file is how the tool knows which secure tag replaces which network tag. Block 3b fills it in and block 3c passes it.
3. Task 6 deletes the old rules. Do not run it until the checks for Tasks 2, 3 and 4 are green: once the old rules are gone you cannot redo a migration.
4. The checker lags. If a check fails, wait 30-60 seconds and click again.

## Setup

Nothing to edit, everything is detected.

```bash
cd ~
gcloud config get-value project > ~/project
gcloud compute instances list --filter="name=client-instance" --format='value(zone.basename())' > ~/zone
gcloud compute instances list --filter="name=web-server" --format='value(networkInterfaces[0].networkIP)' > ~/webip
head ~/project ~/zone ~/webip
```

You should see your project ID, a zone and the internal IP of web-server.

## Task 1. Assess the environment

Run the lab's list command with its copy button. You should see three rules: allow-internal-vpc (no tags), allow-web and allow-ssh (tagged). No checkpoint.

## Task 2. Phase 1: migrate the untagged rule

Run the lab's two commands with their copy buttons: the one that writes exclude.txt, then the migrate command. (The lab's command has --force twice, that is harmless.) Then confirm:

```bash
gcloud compute network-firewall-policies rules list --firewall-policy=my-fw-policy --global-firewall-policy \
  --format='table(priority,direction,action,description)'
```

You should see the policy my-fw-policy with a rule that came from allow-internal-vpc, and nothing from allow-web or allow-ssh yet.

Check my progress: Migrate untagged rules using exclusion filters.

## Task 3. Phase 2: migrate the tagged rules

### 3a. Export the tag list, create the secure tag key and values

```bash
cd ~
gcloud beta compute firewall-rules migrate --source-network="unified-network" \
  --export-tag-mapping --tag-mapping-file=tag_map.json
gcloud resource-manager tags keys create vpc-tags --parent=projects/`cat ~/project` \
  --purpose=GCE_FIREWALL --purpose-data=network=`cat ~/project`/unified-network
gcloud resource-manager tags values create web --parent=`cat ~/project`/vpc-tags
gcloud resource-manager tags values create ssh --parent=`cat ~/project`/vpc-tags
gcloud resource-manager tags values create external --parent=`cat ~/project`/vpc-tags
gcloud resource-manager tags values create internal --parent=`cat ~/project`/vpc-tags
gcloud resource-manager tags values list --parent=`cat ~/project`/vpc-tags --format='value(shortName,name)'
cat tag_map.json
```

You should see four values (web, ssh, external, internal), each with a tagValues/ number, and then the exported file listing the old network tags with nothing mapped to them yet.

### 3b. Fill in the mapping file

For every old network tag in the file, this looks up the secure tag value with the same name and writes its ID next to it.

```bash
cd ~
cat > fill_map.py <<'EOF'
import json, os, subprocess
proj = open(os.path.expanduser("~/project")).read().strip()
m = json.load(open("tag_map.json"))
for k in m:
    r = subprocess.run(["gcloud", "resource-manager", "tags", "values", "describe",
                        proj + "/vpc-tags/" + k, "--format=value(name)"],
                       capture_output=True, text=True)
    m[k] = r.stdout.strip()
json.dump(m, open("tag_map.json", "w"), indent=1)
print(json.dumps(m, indent=1))
EOF
python3 fill_map.py
```

You should see every tag paired with a tagValues/ number. If any is empty, that network tag has no secure tag value with the same name: tell the author, do not continue.

### 3c. Migrate the tagged rules

```bash
cd ~
gcloud beta compute firewall-rules migrate --source-network="unified-network" \
  --target-firewall-policy="my-fw-policy" --tag-mapping-file=tag_map.json
gcloud compute network-firewall-policies rules list --firewall-policy=my-fw-policy --global-firewall-policy \
  --format='table(priority,direction,action,description)'
```

You should see rules from allow-web and allow-ssh in the policy now, next to the one from allow-internal-vpc.

Only if 3c stops with an error saying the policy my-fw-policy already exists: the tool wants to create the policy itself. Delete the Phase 1 policy and run 3c again, it then migrates all three rules in one go (your Task 2 check stays green).

```bash
gcloud compute network-firewall-policies delete my-fw-policy --global --quiet
```

Check my progress: Migrate tagged rules using secure IAM Tags.

## Task 4. Associate the policy

Run the lab's two commands with their copy buttons (associate, then change the enforcement order). Then confirm:

```bash
gcloud compute networks describe unified-network --format='value(networkFirewallPolicyEnforcementOrder)'
gcloud compute network-firewall-policies describe my-fw-policy --global --format='value(associations[].attachmentTarget.basename())'
```

You should see BEFORE_CLASSIC_FIREWALL and unified-network.

Check my progress: Associate and prioritize the global network firewall policy.

## Task 5. Test and verify (no checkpoint)

One line connects to client-instance and asks web-server for its page.

```bash
gcloud compute ssh client-instance --zone=`cat ~/zone` --quiet \
  --command="curl -s -m 10 -I http://`cat ~/webip` | head -1"
```

You should see an HTTP line such as HTTP/1.1 200 OK. Then follow the lab: Logs Explorer, search resource.type="gce_subnetwork", and look for my-fw-policy in the entries.

## Task 6. Clean up

STOP: only continue when the checks for Tasks 2, 3 and 4 are green.

```bash
gcloud compute firewall-rules update allow-internal-vpc --disabled
gcloud compute firewall-rules delete `gcloud compute firewall-rules list --filter="network:unified-network" --format='value(name)'` --quiet
gcloud compute firewall-rules list --filter="network:unified-network"
```

You should see "Listed 0 items." The old rules are gone and only the policy protects the network.

Check my progress: Clean up legacy VPC firewall rules.
